# Fronteira proposta de extração

## Regra da decisão

Esta é uma classificação arquitetural, **não autoriza mover código**. A decisão aplica-se a cada um dos mesmos 28 componentes do inventário. Em packages mistos, `MOVE_WITH_REFACTOR` significa separar primeiro a porção neutra e manter a porção de produto; não significa copiar o package inteiro. `ADAPTER_ONLY` significa preservar uma implementação concreta atrás de port neutro. Risco mede dano potencial; dificuldade mede esforço/incerteza. Toda decisão permanece condicionada a behavioral freeze, contracts neutros, manifests corretos, consumer tests e rollback.

## Resumo MOVE/KEEP e direção alvo

| Disposição               | Componentes                                                                                                                                             |
| ------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `MOVE_AS_IS`             | nenhum componente: todo candidato exige ao menos estabilização de contrato/ownership                                                                    |
| `MOVE_WITH_REFACTOR`     | `agent-evals`, `agent-runtime`, `approval-engine`, `channel-gateway`, `chaos`, `model-gateway`, `observability`, `platform`, `policy-engine`, `scripts` |
| `REIMPLEMENT_IN_HARNESS` | `memory`, capability/tool core hoje em `tools`, configuração raiz                                                                                       |
| `KEEP_IN_SECRETARY`      | `apps/api`, `apps/web`, `apps/worker`, `rag`, `workflows`, `tests`, `docs`, `deploy`, `certification`                                                   |
| `KEEP_SHARED_CVG_DOMAIN` | `shared`                                                                                                                                                |
| `ADAPTER_ONLY`           | `adapters`, `persistence`                                                                                                                               |
| `DEPRECATE`              | `agent-core`, `policy`, somente depois de paridade e rollback                                                                                           |
| `UNKNOWN`                | infraestrutura dedicada                                                                                                                                 |

Direção obrigatória após a extração:

```text
Secretary hosts/profile/skills/workflows
  -> Harness contracts/runtime/governance
    -> neutral ports
      -> Secretary/provider adapters
        -> external systems
```

São proibidas dependências `HARNESS -> Secretary`, `HARNESS -> product UI/workflow` e storage core conhecendo implementations superiores. `shared` não deve ser usado como atalho para importar todo o domínio CVG.

## Ordem segura e gates de entrada

1. Congelar comportamento e APIs públicas do approval/runtime/model/policy/effects, corrigir manifests e provar o caminho público HTTP→SQL→worker→kernel.
2. Definir contracts/ports neutros e dependency rules; criar consumer-contract suite Secretary antes de mover bytes.
3. Extrair `approval-engine` primeiro com store adapter e rollback. Depois model/observability/policy mechanism; runtime somente após seus dependencies.
4. Reimplementar capability registry e memory como novos componentes especificados; não promover os stubs/handlers atuais.
5. Recompor API/worker Secretary com dual-path/differential evidence; deprecar `agent-core`/`policy` somente depois de paridade.
6. Validar um segundo cliente conceitual/executável sem adicionar requisitos de produto ao core; só então avaliar extração de control plane e infraestrutura.

Nenhum package deve ser movido agora. O kernel atual não deve ser promovido a runtime canônico até o caminho público, crash/replay, approvals, effects, tenant isolation e rollback estarem demonstrados com evidência atual.
