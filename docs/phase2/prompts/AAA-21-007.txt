tentar ativamente encontrar:

A. hidden synchronous execution path;
B. second non-canonical Worker path;
C. tool execution bypass;
D. direct provider bypass;
E. policy bypass;
F. approval replay;
G. duplicate effect after crash;
H. stale Worker commit after lease loss;
I. tenant leakage;
J. idempotency race;
K. illegal state transition;
L. terminal state resurrection;
M. audit event emitted before causal action;
N. telemetry claim inconsistent with persistence;
O. fake restart proof;
P. fake PostgreSQL proof using in-memory substitute;
Q. evidence generated from stale code;
R. docs claiming behavior not covered by executable proof.

Qualquer finding crítico deve bloquear APPROVE até reparo ou classificação
honesta como NOT_PROVEN quando permitido.

"tente encontrar razão técnica para rejeitar".
