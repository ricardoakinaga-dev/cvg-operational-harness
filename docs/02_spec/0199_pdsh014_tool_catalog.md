# 0199 — SPEC: PDSH-014 — Catálogo gerado de ferramentas e skills com drift-check

- Task: `PARE-DSH-20261011`, cartão `PDSH-014` (plano [0375](../03_build/0375_plano_pareamento_motor_dsh.md), Onda 2, trilha T2).
- Dependências `DONE`: PDSH-012 (fs tools), PDSH-013 (shell tool), PDSH-015 (skills filesystem).
- Padrão dsh `tool-catalog`: o catálogo é **gerado a partir do código-fonte real** e o CI falha em drift (tipo novo sem entrada, ou entrada sem tipo). Invariantes: ADR-010 (`boundary:products`), fail-closed, produção `NO_GO`, sem dado real, `products/**` intocado.

## Objetivo

Publicar um catálogo canônico de **tools** (descritores de capacidade executável) e **skills** (descritores de requisito/risco, ADR-003) em `docs/architecture/TOOL_CATALOG.md`, gerado por um script determinístico a partir do repositório, com um **drift-check** que falha quando o catálogo commitado diverge do que o gerador produziria hoje.

## Decisões de design

### 1. Fontes de verdade (o gerador lê o código, não uma lista manual)

| Tipo   | Fonte                                                                     | Extração                                                                                                                                             |
| ------ | ------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------- |
| Tools  | `packages/sandbox/src/fs-tools.ts` e `packages/sandbox/src/shell-tool.ts` | parsing determinístico dos literais de descritor (`id`, `version`, `description`, `risk`, `sideEffect`, `idempotent`, `requiresApproval`, `sandbox`) |
| Skills | `skills/<id>/skill.json` (carregador de PDSH-015)                         | `JSON.parse` direto; mesmo vocabulário fechado                                                                                                       |

- O gerador **não** duplica o catálogo numa lista à mão: os descritores vêm do código que o kernel executa. Drift real (tool nova sem entrada) é capturado porque o parsing falha ou a comparação diverge.
- Ferramentas fora de `@cvg/sandbox` (capacidades do kernel como `model`, `planner`, `tools`) **não** entram neste cartão: o catálogo cobre o runtime de ferramentas do sandbox (fs/shell) + skills do diretório `skills/`. Expansão é cartão futuro.

### 2. Formato do catálogo (`docs/architecture/TOOL_CATALOG.md`)

- Cabeçalho fixo: `<!-- GENERATED by scripts/gen-tool-catalog.mjs; DO NOT EDIT BY HAND -->`.
- Duas seções: `## Tools` e `## Skills`.
- Tools: tabela com `id`, `version`, `risk`, `sideEffect`, `idempotent`, `requiresApproval`, `sandbox`, `description`.
- Skills: tabela com `id`, `version`, `riskLevel`, `requiredTools`, `requiredKnowledge`, `description`.
- Ordenação determinística: tools e skills por `id` crescente (o gerador ordena; o diff é estável).

### 3. Gerador (`scripts/gen-tool-catalog.mjs`)

```bash
node scripts/gen-tool-catalog.mjs            # gera/atualiza TOOL_CATALOG.md
node scripts/gen-tool-catalog.mjs --check    # drift-check: exit 1 se divergir
```

- Parsing: extrai os campos dos literais TS por regex determinístico (sem importar o pacote — o script roda em Node puro, sem build prévio; o regex é específico o suficiente para os literais deste repositório e falha ruidosamente se o formato mudar).
- Skills: lê `skills/*/skill.json`; id do manifesto deve igualar o nome do diretório (mesma regra de PDSH-015).
- `--check` compara o conteúdo gerado em memória com o arquivo commitado (normalizando EOL); divergência → imprime os dois lados e exit 1.
- Determinístico: mesma árvore → mesmo bytes (sem timestamps, locale ou ordem de filesystem).

### 4. Gate

- Novo script `scripts/check-tool-catalog.mjs`? **Não** — o próprio `gen-tool-catalog.mjs --check` é o gate (um arquivo, dois modos).
- Ponto de extensão: se existir um aggregator de gates (ex.: `ci-bar`), registrar o drift-check; se não, o gate roda via `npm run tool-catalog:check` e é referenciado no `verify`/CI bar de PDSH-033. **Neste cartão**: adicionar o script ao `package.json` (`tool-catalog` e `tool-catalog:check`) e, se o `verify` atual permitir, encadear `tool-catalog:check` — sem reescrever o CI bar.

### 5. O que este cartão NÃO faz

- **Não** adiciona o gate ao `.github/workflows/verify.yml` nem ao `ci-bar.mjs` (isso é PDSH-033).
- **Não** cataloga capacidades do kernel (`model`, `planner`, `tools`) nem produtos.
- **Não** muda nenhum contrato público de `@cvg/sandbox`/`@cvg/harness` (o catálogo é documentação gerada, não API).
