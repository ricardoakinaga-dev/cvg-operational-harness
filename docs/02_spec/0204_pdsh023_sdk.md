# 0204 — PDSH-023: SDK de integrador (JSON-RPC v1, cliente TS, composições `sdk`/`sdk-minimal`)

- Task `PARE-DSH-20261011`, cartão PDSH-023, Onda 3 do [plano 0375](../03_build/0375_plano_pareamento_motor_dsh.md), trilha T3.
- Dependências `DONE`/`DONE_LOCAL`: PDSH-001 (kernel único de composição) e PDSH-021/022 (store append-only e evolução de formato). Reusa `createOperationalHarness`, `createSessionKernelLog` e o catálogo de eventos de sessão.
- Invariantes: ADR-010/011 (superfície pública do núcleo; sem spine paralelo), fail-closed, sem provider real (gateway determinístico no exemplo), sem dado real, `products/**` intocado, push/deploy/release não autorizados, produção `NO_GO`.

## 1. Recon

- A composição canônica é `createOperationalHarness` (`packages/harness/src/createOperationalHarness.ts`): exige `modelGateway`, `policy`, `approvals`, `tools`/`capabilities`, `audit`, `telemetry`; resolve `single_pass` por padrão. `createSessionKernelLog` liga o `KernelLog` a um stream de sessão por turno (PDSH-021).
- O padrão HISO-009 (`examples/consumers/reception-agent` + `tests/consumers-public-surface.test.ts`) exige: consumo só pela raiz dos pacotes listados em `PUBLIC_API.md`, sem `products/**`, sem `/src/`, sem rede real; o teste público valida a lista nominal contra os entrypoints e o exemplo neutro.
- Não existe protocolo de integrador: hosts falam com o harness por composição direta em processo. Fora do monorepo não há contrato versionado de sessão/turno.

**Decisão:** novo pacote neutro `packages/sdk/**` (`@cvg/sdk`) com um protocolo JSON-RPC 2.0 **v1** explícito (`sdk.hello`, `session.open`, `turn.send`, `session.events`), servidor que nunca lança, cliente TS tipado e transporte em processo para demos/testes. Duas composições: `createSdk` (com sessão/eventos) e `createSdkMinimal` (sem sessão). Hosts reais plugam seus próprios transportes (HTTP/stdio) no contrato `SdkTransport`; nenhum transporte de rede entra neste cartão.

## 2. Protocolo v1

- Envelope JSON-RPC 2.0 estrito: `jsonrpc: '2.0'`, `id` string|number obrigatório, `method` string. Lote/array, notificação sem `id` e envelope inválido → `-32600`. Método desconhecido → `-32601`. Params inválidos → `-32602`. Handler que lança → `-32603` (nunca propaga exceção).
- `sdk.hello { protocolVersion }` → `{ protocolVersion: 1, capabilities }`; versão diferente → `1001 unsupported_protocol_version`. É a negociação de versão do protocolo.
- `session.open { sessionId }` → `{ sessionId, formatVersion: 1 }` (idempotente; formato divergente é erro).
- `turn.send { sessionId?, userMessage }` → `{ stopReason, response, modelCalls, toolCalls, usage, sessionId? }`. Constrói `RuntimeInput` sintético (agente padrão substituível, orçamento padrão substituível), apenda `message/user` antes do turno e, quando o turno conclui `COMPLETED`, `message/assistant` depois; executa um harness por turno com o log ligado à sessão (eventos do kernel: `turn/start`, `model/request`, `model/result`, `turn/end`). Falha de modelo permanece resultado fail-closed (`MODEL_FAILURE` no `turn/end`), nunca exceção.
- `session.events { sessionId, afterSequence?, limit? }` → `{ events }` (ASC por sequência; teto 500; store é a autoridade).
- Códigos extras estáveis: `1002 session_not_found`, `1003 capability_not_available` (método de sessão em composição mínima).
- `capabilities`: `{ sessions, events, methods }`; a composição mínima só anuncia `sdk.hello` e `turn.send`.

## 3. Contrato e composições

```ts
export function createSdkServer(options: SdkServerOptions): SdkServer
export function createSdkClient(transport: SdkTransport): SdkClient
export function createInProcessTransport(server: SdkServer): SdkTransport
export function createSdk(options: SdkCompositionOptions): SdkFacade
export function createSdkMinimal(options: SdkMinimalOptions): SdkMinimalFacade
```

- `SdkServerOptions`: `tenantId` (obrigatório), `modelGateway`/`policy`/`approvals` (obrigatórios — governança visível), `agent?` parcial, `tools?` (padrão registry vazio), `audit?`/`telemetry?` (padrão sinks inofensivos), `sessions?` (habilita `session.open`/`session.events`), `budget?`, `clock?`, `newEventId?`/`newCorrelationId?`/`newTraceId?` (injetáveis para determinismo).
- `createSdk` usa `InMemorySessionEventStore` por padrão (`sessions` substituível). `createSdkMinimal` não tem sessão por tipo.
- Cliente: `hello()`, `openSession(sessionId)`, `sendTurn(userMessage, sessionId?)`, `readEvents(sessionId, options?)`; resposta de erro vira `SdkClientError` com `code`.
- Tenant é vinculado na composição (nunca vem do pedido). Sem tenant real; auth do transporte fica com o host.

## 4. Exemplo de consumidor (HISO-009)

`examples/consumers/sdk-session/index.ts` compõe por `@cvg/sdk` + tipos de `@cvg/harness-contracts` apenas: gateway determinístico (`externalCall: false`), policy sintética, approvals sintética que nega efeitos, clock/ids fixos. O journey: `openSession` → `sendTurn` → `readEvents`, mais um turno na composição mínima. Teste dedicado `tests/consumers-sdk-session.test.ts` verifica sequência imutável de eventos (`message/user`, `turn/start`, `model/request`, `model/result`, `turn/end`, `message/assistant`), ausência de rede e imports só de raízes públicas.
