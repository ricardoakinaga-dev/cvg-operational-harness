**Behavioral cases for future acceptance**

These are source-derived expectations, **not executed results**.

| Case | Expected |
|---|---|
| `result:"bytes"` alone | Inline. |
| `fileId:"file-1"` alone | File; serialization omits `result`. |
| Both strings, including empty or stale `result` | File wins. Rust deserialization order matters; JSON Schema array order does not impose precedence. |
| `fileId:null`, valid `result` | Inline fallback; explicitly tested. |
| Neither representation, or neither branch has a valid string | Deserialization failure. Empty strings themselves have no public validation constraint. |
| Missing `inputImages` / `[]` | Empty vector; omitted on serialization. |
| `inputImages:null` / malformed entries | Rejected by nonnullable Vec/required entry fields. No SHA length/hex validator in the public type/schema. |
| Relative input path | Requires deserialization base guard; otherwise rejected. Guard may resolve it—do not assert universal relative-path rejection (`utils/absolute-path/src/lib.rs:346,396`). |
| Upload returns File / Inline / error | Public item follows File / encoded Inline / original Inline fallback. |
| Started / backend-failed item | Empty Inline result and empty observations; source emits `in_progress` / `failed`. Public `status` remains unrestricted String. |
