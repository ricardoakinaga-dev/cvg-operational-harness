## Startup fail-closed (explicit proof)

- Unit/spawn: `continuous-worker.test.ts > exits non-zero when the real entrypoint starts without
required config` spawns `apps/worker/src/main.ts` with `CVG_WORKER_RUN_MODE=continuous`,
  `CVG_WORKER_QUEUE_ADAPTER=postgres-controlled`, valid tenant/RLS/controlled-mode and empty
  `DATABASE_URL`; asserts exit code 1 and JSON line
  `{"event":"worker.startup_failed","code":"postgres_database_missing",...}`.
- Smoke: `npm run test:worker:startup` proves the adapterless entrypoint exits 1 with
  `queue_adapter_missing`.
- Additional gates: unsupported run mode, non-durable adapter in continuous mode and invalid
  `CVG_WORKER_*` settings all fail before any connection is opened.

## E2E harness (reproducible shape)

The E2E harness is intentionally not committed (task rules: task-owned diff only). It performed:

1. `runPostgresMigrations(client, { schemaName })` on a fresh `cvg_worker_e2e_*` schema.
2. Enqueued two synthetic `message.outbound` events through `TenantScopedPostgresRuntimeRepository`.
3. Spawned `./node_modules/.bin/tsx apps/worker/src/main.ts` with:
   `DATABASE_URL=$TEST_DATABASE_URL POSTGRES_SCHEMA=<schema> POSTGRES_RLS_ENFORCEMENT=true
CVG_WORKER_CONTROLLED_MODE=true CVG_WORKER_QUEUE_ADAPTER=postgres-controlled
CVG_WORKER_RUN_MODE=continuous CVG_WORKER_TENANT_ID=… CVG_WORKER_ID=worker-e2e-193
CVG_WORKER_POLL_INTERVAL_MS=20`
4. Waited for `worker.continuous_ready` and both `worker.outbox.processed` lines, sent `SIGTERM` to
   the node PID, observed exit 0 and `worker.shutdown.completed`.
5. Verified both events `processed` through a second repository instance and dropped the schema.
