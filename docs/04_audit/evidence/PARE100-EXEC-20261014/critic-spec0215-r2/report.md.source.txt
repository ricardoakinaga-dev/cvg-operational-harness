## Concrete site qualification and trust limits

The stubborn test child uses the current Node executable, a fixed `-e` string, pipes, a private cwd and an explicit four-key environment; it does not inherit NODE_OPTIONS. Cleanup is registered locally; readiness has a 2000 ms deadline and removes its data/error/close listeners ([stdio.test.ts:150–204](../critic-spec0215-r2-packet/packages/sdk/src/__tests__/stdio.test.ts#L150)). The string ignores TERM and keeps the child alive; the spy observes its own child's native kill method. These are suitable bounded capability sites under the trusted native-process premise.

The example takes no caller/RPC spawn options. Its binary is `process.execPath`, argv selects a sibling using `import.meta.url`, no shell is requested, cwd is explicit and env enumerates PATH/NODE_ENV/private HOME/XDG_CONFIG_HOME/TMPDIR ([index.mts:57–108](../critic-spec0215-r2-packet/examples/consumers/sdk-stdio/index.mts#L57)). PATH is inherited intentionally; this is not a hermetic environment. The source branch uses trusted local `tsx`. Public exports/loader/package resolution are trust seams, not containment guarantees. In particular, the `.mjs` branch is present in source but a compiled copy receives no inherited exception: it needs its own byte-qualified review if later included in the closure, as SPEC line 34 already requires.

The local helper drains 1000 ms, TERM 500 ms and KILL 250 ms, waiting for close and verifying exit plus closed stdio; nested finally blocks attempt shutdown even if transport close fails, and successful return follows cleanup ([index.mts:8–55 and 110–123](../critic-spec0215-r2-packet/examples/consumers/sdk-stdio/index.mts#L8)). It accepts any supplied ChildProcess object; qualification applies only to these literal owned-child calls. The private directory removal condition checks recorded exit/signal, not independently successful stdio closure; it must not be described as a guarantee to retain the directory after every possible shutdown error ([index.mts:117–119](../critic-spec0215-r2-packet/examples/consumers/sdk-stdio/index.mts#L117)). This precision limit is nonblocking for the stated confirmed-process-exit condition and trusted synthetic children.

The 13 mirror sites are data reflection: canonical checks ordinary/null prototypes; session examines own descriptors, rejects accessors/non-enumerable values and recursively validates descriptor values. No reflected value becomes a callee or module specifier ([canonical source:26–29](../critic-spec0215-r2-packet/packages/contracts/src/canonical-json.ts#L26), [canonical compiled:23–25](../critic-spec0215-r2-packet/packages/contracts/dist/canonical-json.js#L23), [session source:48–90](../critic-spec0215-r2-packet/packages/harness/src/session/events.ts#L48), [session compiled:17–58](../critic-spec0215-r2-packet/packages/harness/dist/session/events.js#L17)). Visual source/compiled inspection supports these local mirrors. The supplied complete-AST comparison is explicitly static and non-final; I verified its source/compiled byte references, not its transpilation algorithm or AST equality calculation ([compiled-comparison.json:5–19 and 23–37](../critic-spec0215-r2-packet/docs/04_audit/evidence/PARE100-EXEC-20261014/spec0215/compiled-comparison.json#L5)). Proxy/hostile-object safety and module-resolution equivalence are not certified.

## Detector preservation and proposed negative controls

The finite extension is exactly one site path (`examples/consumers/sdk-stdio/index.mts`) and two pin paths (that file plus `child.mts`). Existing packages/apps/legacy grammar and scripts-only-as-pins behavior remain; products, traversal, symlink sites, node_modules and example globs are expressly forbidden ([SPEC:23–28](../critic-spec0215-r2-packet/docs/02_spec/0215_pare100_sdk_boundary_qualification.md#L23), [proposal:206–224](../critic-spec0215-r2-packet/docs/04_audit/evidence/PARE100-EXEC-20261014/spec0215/revision-r2/proposed-exceptions.json#L206), [checker:2543–2579](../critic-spec0215-r2-packet/scripts/check-product-boundary.mjs#L2543)). The existing canonical group retains its reason/sites/counts; its extra session pins strengthen conjunction rather than expand acceptance.

All proposed rows use only `UNVERIFIED_DYNAMIC_CODE_EXECUTION`. Product violations are computed separately; SHIFT diagnostics and unresolved/installed findings have different reasons and cannot match these rows. Existing strict mode bypasses application of the entire table ([checker:1642–1801 and 2587–2605](../critic-spec0215-r2-packet/scripts/check-product-boundary.mjs#L1642)). Applied and unused exceptions are observable. These properties are preserved by the design; future implementation behavior has not been accepted.

SPEC lines 46–51 require concrete known-good, each-pin byte drift, expression-tail change, duplicate occurrence, wrong file/reason, other example/product/script, traversal/symlink, product import/require/dynamic loader, SHIFT, unresolved-module and strict negatives. Requiring each limit independently is appropriate. Implementation evidence must show the specific residual diagnostic/violation and exception use, since a generic nonzero exit caused only by pin drift cannot establish the other matcher/reason controls. No negative was run here; future BUILD checks remain mandatory and unaccepted.
