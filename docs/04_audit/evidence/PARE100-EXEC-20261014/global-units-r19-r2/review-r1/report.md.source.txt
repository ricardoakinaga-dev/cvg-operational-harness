## Strongest material defect: I1-01

In `r2/network-guard.cjs:64-69`, IPC ownership is checked only when `options.port === undefined`. A supplied port instead selects TCP authorization. Line 95 forwards the unchanged `path` to Node's original connect implementation. Node uses that IPC path. A valid owned loopback TCP port therefore authorizes a different transport endpoint.

The byte-identical relocated guard has SHA256 `d60c0d613b54f733e8da8e646d8d4c89be7ae607a2fd3d568cbbc890c8719727`, matching the packet R2 guard. On Node v22.23.2, the private probe created an IPC listener before installing the wrapper, leaving it deliberately absent from the guard registry. It then created registered TCP and IPC listeners. Every endpoint belonged to this probe under the authorized output directory, with TCP bound only to `127.0.0.1` on an ephemeral port; there was no DNS or external endpoint.

Raw observations in `probe/stdout.jsonl`:

- Line 2: registry contains the owned TCP port 33857 and owned `o.sock`, but no `u.sock`.
- Lines 3–4: owned TCP and owned IPC positives connect and receive their distinct payloads.
- Line 5: `{path: u.sock}` is denied with `CVG_GLOBAL_TEST_NETWORK_BLOCKED`, without connecting.
- Line 6: `{path: u.sock, host: '127.0.0.1', port: 33857}` connects and receives `UNREGISTERED_PRIVATE_IPC`.
- Line 7: unregistered IPC accepted exactly one connection; TCP accepted only its positive-control connection. The blocked log contains only the ordinary path-only negative.

`probe/command.json` records the exact argv, minimal environment, 8-second bound, exit 0 and guard hash. Exit 0 records successful probe execution, not verifier approval. `probe/probe.cjs` contains the entire probe. The guard was loaded via `require` after arranging the private unregistered endpoint; the probe validates the installed wrapper's behavior, not startup inheritance. No product implementation or immutable input was changed.

Required revision: authorize the transport Node will actually use, including IPC ownership whenever `path` selects IPC, or reject ambiguous `path`/`port` combinations. Add a mixed-options negative control. This does not require changing the product smoke expectation or synthesizing `ECONNREFUSED`.
