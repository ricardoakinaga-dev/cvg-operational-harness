+### 5.2. Configuração efetiva ligada à identidade nativa de tools
+
+CURRENT: CapabilityRegistry calcula o fingerprint dos descriptors normalizados, incluindo providerId/providerVersion. O adapter de effect journal calcula proposalHash de compositionFingerprint, identidade/metadados da tool e invocation.input; sua chave de reserva é tenantId/operationKey. CONFIRMED com o mesmo proposalHash pode retornar o resultado salvo sem chamar o body atual. planDigest/configDigest/generationId/executionId não entram automaticamente nesse hash. Logo, trocar o target configurado A por B mantendo os mesmos descriptors pode produzir replay de A no turno de B; é uma dedução de fonte, não um exploit executado.
+
+No modo gerenciado, cada provider de ferramentas tem um binding canônico imutável de configuração efetiva, antes de activate. O host confiável captura `journalBindingScopeId`, estável para o escopo compartilhado do journal, e `effectTargetBindings`: mapa JSON estrito de IDs/revisões imutáveis dos recursos/targets configurados usados pelas ferramentas. Não são actor, grants ou handles. Esses dados vêm do catálogo/host, nunca do pedido de turno ou do modelo. O mesmo ID/revisão não pode passar a designar outro target configurado durante o lifetime de qualquer geração ou entre owners que compartilham o journal. Dependência de target que não possa ser declarada e identificada estavelmente torna esse plugin incompatível com este perfil; não usar hash de função, referência de objeto, env mutável ou nome de conexão como substituto.
+
+O configDigest usado aqui cobre TODA a configuração efetiva do plugin, depois de validação/defaults determinísticos, capturada/frozen antes de activate, não apenas a parte fornecida no pedido ou um subconjunto escolhido pelo plugin. artifactSetDigest cobre o conjunto de artefatos revisados que implementa esse provider conforme o catálogo. effectTargetBindingsDigest cobre o mapa canônico de targets capturado pelo host, com os mesmos limites de JSON/config e charge. Mudança de binding não pode ficar escondida em closure ou factory externa enquanto o catálogo declara os dados antigos. Estado operacional normal de um recurso não vira nova configuração por cada chamada; esta regra identifica código/config/target, não promete resultado invariável de uma operação externa.
+
