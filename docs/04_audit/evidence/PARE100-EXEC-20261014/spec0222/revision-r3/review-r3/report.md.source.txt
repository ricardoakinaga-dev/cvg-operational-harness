## F1 — Persistent native abort subscriptions escape the snapshot lifetime/accounting rule

**Priority P2; must correct the contract.** Affected proposed rules: spec.md:60–66, 109, 195–211 and 235–245; future ML11/ML20/ML23. The snapshot budget covers retained turn/profile data and tokens, and refunds follow original producer subtrees. It does not explicitly own, detach or account native event subscriptions that remain after those promises settle. The declared signal exception permits a long-lived caller signal; it does not require a per-turn bridge whose external subscription is detached.

Concrete native seam: `cvg/packages/harness/src/kernel/kernel-runtime.ts:219–231` installs `input.signal.addEventListener('abort', () => this.#controller.abort(), {once:true})`. That closure captures the Turn instance. Turn retains `#state`; `cvg/packages/harness/src/kernel/pipeline.ts:41–51` stores the input directly in that state, including its authenticated AgentProfile and detached context/state snapshot. The kernel-runtime file has no matching removeEventListener. Normal finish (`kernel-runtime.ts:635–671`) does not abort or detach this link. The pipeline's temporary race subscriptions, by contrast, are removed in finally (`pipeline.ts:139–184`). `iterative-runtime.ts:648–653` also adds a persistent link without removal, although that displayed callback captures the controller rather than directly the Turn; the strong full-snapshot retention argument here is specifically single-pass.

Counterexample schedule allowed by the proposed interface:

1. Keep one un-aborted, genuine caller AbortSignal alive. Pin a valid small agent and run a valid single-pass turn with a distinct bounded context and that signal.
2. The native turn succeeds, its original promises and descendants settle, and the accounting releases its turn snapshot charge. The caller discards the turn input and result. The signal still owns the once-listener: once means removed on abort, not on successful completion.
3. Repeat sequentially on the same lease and signal. Concurrent turns, operations and acquires remain below every quota; request/lease lifetime limits do not bound total turns on an existing lease. Each listener nevertheless retains a Turn and its input snapshot. Keeping only the signal alive can therefore retain snapshots from arbitrarily many completed turns while the proposed accounting reports them released.

This schedule is source-grounded static reasoning, **not an executed leak/GC test**. The proposed managed wiring could avoid it, but R3 does not require that correction. Wrapping promise lifetimes alone leaves an implementation that preserves this native link as-is admissible under the described wiring.

**Violated invariant:** retained protocol-owned turn/profile snapshots and native bindings must remain bounded by the owner reservation; true lifetime includes persistent subscriptions retaining those snapshots, not just pending promises. This is narrower than an exact V8 heap or OS-isolation guarantee. It is not a request to account caller copies or hidden port buffers.

**Minimal correction:** specify native signal/abort/timer subscriptions as owned per-turn resources. Require either a detached bridge or an equivalent release of every retaining link on all exits, including normal finish and early error. Preserve cancellation for original work while it is still live; do not detach prematurely at a timeout facade. Only refund snapshot/binding charges after the original subtree is zero **and** retaining subscriptions have been detached or their captured snapshot references severed. Include these handles in admission/accounting before registration. Add a future ML23 case using repeated completed single-pass turns on one never-aborted signal, plus timeout-with-live-original and early-exit controls, checking bounded live subscriptions/reservations without forcing signal abort. No contracts-module change is required by this correction.
