### F4 — P1 — Exact final projection is still not joined to the sealed state

**S:1017,1037–1049,1067–1115,1149–1166. K04/K09/K10. STATIC + TESTED(pure), high confidence.**

The new finalIssued, identity, anchor and mirror checks reject several original invalid cases. However, callback/mirror/journal verification is driven by `t.tools.filter(status !== 'not_run')`, without first requiring the trace's complete tools projection to match the sealed attempts/names. An omitted or `not_run` tool bypasses that loop. The separate journal read at1149 only chooses a failure classification; it does not veto a requested success.

**Discriminating reproduction:** build a synthetic hash-consistent S2 with one successful attempt and the required ACK refs, use the actual frozen snapshot validator and actual checkpoint-integrity dependency, then pass `trace.tools=[]`. Make the audit mirror unrelated and the journal double return UNCERTAIN. `F4-omitted-tools-bypass-callback-join` still reaches the **SUCCEEDED transition request**, with **zero mirror SELECTs**. The same fixture with the tool declared succeeds normally; declared failed callback, foreign mirror, missing mandatory audit, absent finalIssued and foreign snapshot controls reject. The test does not claim a genuine PG state or completed public exploit.

A second omission permits output substitution: only `r.response === t.response.text` is required. `F4-response-diverges-from-sealed-output` changes both strings from the sealed `Synthetic approved reply` to `Different synthetic reply`; success is still requested while the final snapshot retains the original output/digest. Thus the closed trace/result can disagree with the approved output whose digest was certified.

**Impact:** closed success can certify a trace/result that hides a persisted tool attempt or changes the sealed response, and omission defeats the callback/mirror/journal defense. The normal facade currently constructs the expected projection; this is a store-boundary integrity defect, not evidence that arbitrary HTTP callers can supply it.

**Remediation/closure:** derive and compare the exact trace tools and response/mode from the validated anchor/final snapshot before writing `execution.closed`. Join mandatory callbacks and journal facts by the sealed attempts/operation keys, regardless of what the incoming trace lists. Add real-PG omission/not_run, response substitution and contradictory-journal/mirror negatives, requiring parent/binding/closure evidence unchanged on rejection. Do not repair this by weakening the existing checks.

### F3 — P1 — A matching phase name still does not prove plan-seal provenance

**S:884–895,938–957; platform/controlled-kernel-continuation.ts:654–843. K04/K10. STATIC + TESTED(pure), high confidence.**

Foreign checkpoint identity, wrong phase name and invalid checkpoint digest now reject. But `saveResumePoint` checks only `open_phase_type === 'plan.seal'` for S1 and the ACK boolean. Neither it nor `validateSealPayload` compares `open_phase_input_digest` with the snapshot's `{outputDigest,fingerprint}`, or joins the plan intent/result/ACK to those values. The generic validator validates the snapshot/checkpoint against digests constructed from that same candidate; it cannot supply the missing persisted provenance comparison.

**Discriminating reproduction:** `seal-positive-exact-plan-phase` seals S1 for the expected digest. With the same fixture and checkpoint, ACK `plan.seal` for a digest advertising another output and fingerprint, then submit the original internally consistent snapshot. `F3-seal-does-not-bind-plan-phase-input` still invokes the checkpoint writer once and returns a new seal. The actual frozen canonicalizer, snapshot validator and checkpoint-integrity dependency execute; parent/step SQL rows and checkpoint persistence are doubles. The checkpoint fixture is simplified and was not emitted by a running kernel. This proves the predicate omission, not a PG tamper or public-path exploit. The synthetic evidence chain also lacks model predecessor facts; no separate public exploit is inferred from that fixture construction.

**Impact:** the seal certifies an acknowledged phase for different inputs as the plan used by S1, so an input/projection error is made durably resumable rather than rejected before writes. Current facade preparation of the right digest does not make the store's certification exact.

**Remediation/closure:** bind the exact persisted plan intent and ACK/result to the supplied snapshot output/fingerprint/plan and its real checkpoint/step, on the same client before checkpoint/state/seal writes. Preserve the good S1/S2 path and foreign-checkpoint rejection. A real-PG negative with an actual kernel-produced checkpoint must show unchanged checkpoint/binding/seal when only the phase input differs.

### F7 — P2 — Paired renewal ignores kernel expiry/fault and does not clamp inner TTL

**S:544–575; controlled-published-fencing.ts:218–224,296–328**, pin `270ecfbd7351638f4352665be8bc11cfd2521e17ca7fe63388915b8b7798f2f1`. **SPEC2.3.2, K05/K06/N1-R. STATIC + TESTED(pure), high confidence.**

`renewPaired` calls the common guard with `settlement:true`. That deliberately skips dispatch_closed/FAULTED/fault and kernel-expiresAt vetoes. It then updates both inner execution and queue to `DBnow + 10000`, without `min(...,expiresAt)`. This differs from the explicit approved renewal contract: expired kernel or closed/faulted dispatch must not renew; inner TTL is capped at the fixed deadline.

`F7-paired-renewal-expiry-and-fault` observes the two inner lease UPDATE requests in all four cases: live kernel with1s remaining (updated to+10s), already expired kernel, FAULTED binding and dispatch_closed binding. The actual store/common-guard bodies run; renewal transaction/outer renewal are doubles, so no actual COMMIT or pair atomicity is asserted.

**Impact/containment:** persisted lease metadata can outlive the kernel authorization and a caller reaching this seam can renew after a durable veto. This is not evidence of body entry after expiry: active admission, persisted permit minimum and local synchronous guard still deny expired dispatch in the tested profile. Healthy lifecycle stop/join also limits reachability, but is not the required persistence guard.

**Remediation/closure:** use active renewal authority (while still allowing initial pre-prepared state), reject expired/faulted/closed dispatch and clamp execution/inner queue TTL to expiresAt; keep outer renewal and rollback atomic. Prove the cases with real PG and the fixed original deadline, without administrative expiry edits for the native timing acceptance.
