## Findings

1. **P1 / I1-F01 — terminal RESPOND is lost on assembly exceptions.** Exact frozen RR03 and RR07 both stop before model entry, retain the full tool output and confirmed journal, but save cursor/steps **1**, retain accepted RESPOND **2**, and have no native failed RESPOND step. The producer raw proofs show the same gap. Three independent probes reproduce it, including a changed provenance selector. `iterative-dispatch.ts:894` awaits composition before its returned-stop handler; size exceptions at `:1058` and selector validation from `iterative-runtime.ts:1787` escape to the catch at `:982`, bypassing the dispatch-stop state advance at `:1200`. These stores did not fail. This violates the requested truthful terminal response handling; the frozen test only checks the failed-step/cursor invariant for RR06.
2. **P2 / I1-F02 — result-log failure charges two calls for one invocation.** Independent `response-result-log-fails` invokes the public factory's model once. Returned and durable calls are **2**, tokens **73/2**, receipts **0**. The native slot is charged by `kernel/pipeline.ts:625` through `iterative-runtime.ts:523`; `iterative-dispatch.ts:1133` charges another call in its unrecorded branch. Refusal is conservative and native RESPOND2 FAILED exists, but accounting is inaccurate.
3. **P2 / I1-F03 — audit veto and durable terminal truth diverge.** Independent `response-terminal-audit-fails` rejects only `runtime.completed`: returned **INSUFFICIENT_EVIDENCE**, durable **COMPLETED**. The checkpoint save at `iterative-runtime.ts:2259` precedes the audit veto at `:2348`, which changes only the result. Rejecting only RESPOND step audit also leaves native step2 SUCCEEDED/result.steps2 against checkpoint cursor1/accepted RESPOND2. Both use healthy native memory stores. See `findings-private.json` for exact source references, triggers and evidence.
