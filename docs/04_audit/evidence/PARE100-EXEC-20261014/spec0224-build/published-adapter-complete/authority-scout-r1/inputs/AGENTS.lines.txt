1: # AGENTS.md — CVG Operational Harness
2: 
3: Este repositorio opera pelo pipeline CVG documentado em `docs/07_agents/AGENTS.md`.
4: 
5: Direção vigente: `docs/architecture/adrs/ADR-010-harness-product-isolation.md`.
6: O harness é infraestrutura reutilizável; o Assistente de Plantão é consumidor

9: 0368 e decisões D1–D4 pertencem ao produto; nenhum release é concedido pela
10: separação. Carteira de transição: `docs/03_build/0370_harness_product_isolation_backlog.md`.

12: Antes de qualquer alteracao, o agente deve ler:
13: 
14: - `docs/07_agents/AGENTS.md`

19: Regras principais:
20: 
21: - Seguir `DISCOVERY -> PRD -> SPEC -> BUILD -> AUDIT`.
22: - Nao iniciar codigo sem gate aprovado e task registrada.
23: - Nao usar dados reais.
24: - Nao liberar producao irrestrita.
25: - Nao confirmar, cancelar ou reagendar consulta real automaticamente.
26: - Nao responder RAG sem fonte institucional aprovada.
27: - Nao executar acao clinica, financeira ou prontuario definitivo.
28: - Toda acao sensivel exige approval ou handoff.
29: - Ao final de qualquer rodada, atualizar runtime state, execution log, backlog quando aplicavel e evidencias.

31: ## Trabalho simultâneo com outros agentes
32: 
33: Codex e Claude Code trabalham ao mesmo tempo neste repositório, no mesmo
34: diretório e no mesmo `main`. Antes de alterar qualquer arquivo, leia e siga
35: `docs/08_runtime/agent_coordination.md`:
36: 
37: - registre um claim com a tarefa e os caminhos antes de começar;
38: - faça commit apenas dos arquivos que você alterou (`git add <caminho>`), nunca
39:   `git add -A`, `git add .` ou `git commit -a`;
40: - não use `git checkout --`, `git restore`, `git stash`, `git reset` ou
41:   `git clean` em arquivos de outro agente, nem reescreva histórico;
42: - `certify`, `test:e2e`, `sbom`, `licenses:check` e mudanças no lockfile só com
43:   claim próprio; push só com autorização do usuário.
