## Rejected expansions

Do not select a Hybrid free-form tool loop, replace the actual consumer with
a generic prepared fixture, rename the SQL marker, create a second budget
store/admission owner, copy full arbitrary JSON into every event, upgrade
legacy turns in place, add a new production tool/provider or claim billing
qualification. Those alternatives do not solve this bounded contract need
and enlarge the approval/verification surface.

The remaining gaps are explicit gate/implementation/evidence dependencies.
No risk rating is an acceptance or an authorization to proceed.
