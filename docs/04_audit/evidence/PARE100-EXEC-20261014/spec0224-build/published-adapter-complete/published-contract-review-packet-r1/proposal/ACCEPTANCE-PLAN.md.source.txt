## Fixture, observation and evidence contract

Future execution requires approved concrete SPEC, registered BUILD task,
disjoint code/resource claim, Node22 and a newly allocated dedicated
loopback PostgreSQL synthetic database/schema/service principal. No use
of existing217/224 resources by inference. No real provider/data/channel or
production. Serving principal must be non-owner, NOSUPER/NOBYPASS/NOINHERIT,
no memberships, explicit minimal grants, forced tenant RLS. Admin setup
and read-only inspection are separately labeled, not the only security
proof. Preserve source, failed runs, data and native resource cleanup.

Use the actual synthetic API signed ingress and actual worker process
entrypoint/queue handler as in T01/T02, then native outer claim, facade,
configured preparation, public factory, tool pipeline, journal, PG CAS,
resume seal, callback mirror, native close, completion and ACK. Public
API request carries only existing fields. Tests may publish a real
synthetic version/config in the actual control-plane store and configure
the new trusted server selector. Do not invoke inboundProcess directly as
the sole vertical proof; do not inject a prepared host result, start a
parent manually in place of worker admission or return a manufactured trace.

Only model/counter are declared synthetic pair substitutions. The unchanged
actual constant tool is a real dispatched native body in the positive
slice. Observers may capture IO, count calls or hold a barrier **after an
actual operation**; they must delegate to the original native operation and
preserve exact arguments/results/COMMIT. Fault wrappers may throw/drop ACK
at identified seams; they cannot implement CAS/fence/journal/close for the
subject. No overwritten handler/validator/body in an actual-tool positive.
Separate lower-level adversarial fixtures must be labeled as such.

Capture raw synthetic body output; full ModelRequests/ModelResults and
counter measurements; checkpoint logical/physical rows at each boundary;
admission/prepared/snapshot/seal; native effect/journal/approval receipts;
audit/log/tool mirror ACKs; parent/inner queue/outer event/attempt/effect
marker rows; DB timestamps, backend PID, OS PID/exit/signal and source
manifest. Compare full canonical value/bytes/digest independently of the
native decoder. Do not rely only on a successful process exit, a rendered
summary or assertions printed by the builder.

Observe before/after COMMIT on actual connections. Read RESERVED from a
second authenticated service connection before model entry. Independent
verification reconstructs request digest, token counts, usage totals,
phase/seal hash chain and row identities. Read-only SQL observation and
synthetic admin inspection supplement serving-role observations; neither
replaces actual locks/claims/CAS. Instrumentation is user-space evidence,
not an OS attestation or malicious in-process plugin isolation.

## Future checks and scope of acceptance

After BUILD authorization, the executor freezes exact sources/commands and
per-case IDs before execution. Root `package.json` T05 defines Node22
typecheck/lint/npm test/test:postgres/test:e2e/certification expectations;
none ran here. Existing generic `.integration.ts` fixtures must not be
assumed included by the default test globs or root PG list. New actual
consumer tests should be explicitly selected and evidenced under an
isolated claimed test profile, alongside pertinent existing217 regressions.
Missing resource, skipIf, zero selected tests or bootstrap failure is
NOT_RUN/FAIL as applicable, never a passing PostgreSQL gate. No pins,
denominators, validators or existing red evidence may be rewritten to
make a gate green.

The lead must reconcile source-bound native pipeline and outer-claim
callers when freezing the executable plan. Exact new test filenames,
commands and resource IDs will be a BUILD-plan artifact after approval,
not nonexistent executable commands advertised by this document.
Typecheck, lint, regression, actual PostgreSQL, E2E, required certification,
independent critique and runtime acceptance all remain NOT_RUN here.

PA01–PA14 can support only a **local bounded synthetic consumer** acceptance
after actual evidence and review. PA15 and its pending dependency remain
visible for full-domain adoption. Neither scope closes fullTR, all36 cards,
parity, global gates or release. Technical SPEC approval and runtime
acceptance must be recorded as separate decisions by their proper owners.
