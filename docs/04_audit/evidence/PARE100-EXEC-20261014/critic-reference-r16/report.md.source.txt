## I1-R16-01 — MEDIUM — Declaration-only selector spelling is discarded

Frozen case B requires preservation of a genuine literal selector/type constraint; only unresolved dual roles require UNKNOWN. The helper's type printer instead treats a spelling whitelist as a necessary condition for preserving even a declaration-only literal.

Inert witness source path: `packages/core/example/src/types.ts`, within the otherwise valid pinned synthetic input/owner setup defined in the sealed tests. The witness was described, never written as a fixture or executed.

```ts
export type Selector = 'throw 0';
```

The literal occurs only as the constraint of an exported type alias. There is no initializer, runtime expression or source-consuming call in this physical source. Whether its bytes also form a program in another language is irrelevant to this established declaration role.

Exact connected derivation from `scripts/reference-contract-catalog.mjs`:

1. Lines 254–275 admit the source. Lines 1608–1651 authenticate/read it and connect it to `extractTypeScriptContracts`.
2. Lines 738–785 establish the source-local literal index. Type syntax is skipped at 744–750, and this source supplies no runtime payload collision.
3. Lines 847–859 recognize the type alias as kind `type`, symbol `Selector`, and pass its declared type to `printed`.
4. Lines 558–573 visit the StringLiteral. The payload collision test is false, but `throw 0` fails `/^[A-Za-z0-9_$./:@-]{1,200}$/` because of the space. The literal is added to the opaque list.
5. Lines 581–585 return the UNKNOWN object below. Lines 960–965 and 1580–1605 carry it into the catalog. The symbol, source and owner remain; the exact selector value does not.
