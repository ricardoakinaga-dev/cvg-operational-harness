## Largest material gap: I1-01 — SD07 discrimination

**MEDIUM severity; HIGH confidence.** `review-packet/procedures.json:390`, `:392`, `:396` describe ordinary JSON followed by caller mutation during pending backend work. Reference `packages/session/session-persistence/src/storage-contract.ts:106` and `:123` separately require single-traversal header/batch materialization; the append contract explicitly addresses rereading accessors between checking and copying.

Rejecting example: a hypothetical adapter validates A synchronously, copies A in a second synchronous traversal, then awaits IO. Mutating the original to B after invocation still persists A, exactly as a single snapshot does. It can also reject all listed ordinary non-JSON and invalid-createdAt controls. The proposed transcript therefore does not establish the stated traversal obligation. With a per-access-changing value, the two traversals can see different values. This is a logical witness, not execution of a reference or CVG adapter.

Add an independently observable adversarial witness and a synchronous check-then-copy negative control. Qualify the permitted-input behavior of the materializer closure before specifying whether the witness is captured or refused; this review did not load the imported snapshot utility and does not invent an accessor acceptance/refusal rule. Alternatively retain this exact obligation as an explicit semantic gap. Asynchronous caller-mutation testing should remain for the distinct alias/await obligation.

## I1-02 — default read vector decoding

**MEDIUM severity; HIGH confidence.** `review-packet/procedures.json:987`–`:989` supplies null offset/length for a successful full read. The actual contract at reference `packages/session/session-persistence/src/handle.ts:77` and `:83` is optional numeric arguments. A direct `read(null,null)` is not a valid positive typed consumer call. No null-to-omission rule is specified. Use an explicit no-argument descriptor, or document a lossless vector decoding rule before invoking either public API. Do not add a public null-acceptance requirement.

## I1-03 — sealed manifest namespace

**LOW severity; HIGH confidence; informational to the semantic decision.** `review-packet/manifest.json:8` binds the artifact manifest hash to the envelope's own basename. Hashing that sealed path does not match. The live artifact manifest does match its advertised digest; the other eight sealed payloads match. Package the two manifests under distinct names in the next packet. No packet files were changed by this review.
