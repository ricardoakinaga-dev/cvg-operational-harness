# Capture and ordering limits

All shell calls used D as cwd. The initial shell was Python 3 in D. The first invocation verified/persisted the expected manifest hash; the next persisted 28 packet hashes and exact 29-file membership and read only integrity metadata. The 111-check initial phase was completed and persisted before the first semantic read of governance/requirements/procedures/native source. Thus bootstrap was split across invocations rather than completing every check in the first shell.

The initial heredocs used to establish the capture wrapper and static readers were not themselves subprocess-captured. Their successful exits and stdout/stderr were observed in the tool transcript. bootstrap-invocations.json records reconstructed commands and output where available, plus exact generated file bodies; it truthfully identifies two source-construction heredocs whose exact shell quoting remains in the conversation tool transcript only. Python stdin argv is ['-']; the heredoc is not part of that argv. The wrapper does not claim to know the shell launcher's internal argv.

Subsequent command-*.json/.stdout/.stderr files preserve exact child argv (including -c source), cwd, exit and complete stdout/stderr bytes. No child capture truncation was applied. Several large tool-display results were truncated above those files; those display truncations are not successful semantic inspection of omitted text. Necessary semantic content was re-read in smaller blocks and structured summaries; data equality was checked on full in-memory JSON rather than tool-display prefixes.

The finalization entrypoint and its exact invocation are separately recorded in finalization-command.json. No package engines, helpers, probes or native binaries were executed/imported. Only reviewer-owned documentary Python scripts ran. None of the 12 proposed procedures ran.
