## Strongest counterexample: endpoint mismatch

The guard chooses host = options.host || options.hostname || localhost ([raw guard](../review-packet-r1/current/network-guard.cjs), line 61). If that value is an IP, it checks ownership and bypasses its lookup wrapper (lines 68–80). Actual Node v22.23.2 chooses only options.host || localhost ([embedded runtime](node22-net.js), line 1313). This is a transport-selection difference, not a source-history inference.

In the bounded probe an unregistered IPv4 stand-in was listening before guard installation. A guarded server then owned ::1 on the same port. net.connect({hostname:"::1",port:44757,autoSelectFamily:false,lookup:pinIPv4}) passed validation against ::1, but Node invoked the untouched pin with localhost and connected to 127.0.0.1:44757. The stand-in accepted exactly one connection. [Raw probe output](probes.stdout.log), lines 21–24, shows the owned control, CONNECTED result, actual remote endpoint, lookup arguments and unownedAcceptDelta=1. [Registry](run-network.jsonl), line 4, registers ::1:44757 only; [blocked log](run-blocked.jsonl) has the earlier ordinary denial of 127.0.0.1:44757 but no denial of the bypass.

F01 requires validating the destination actually selected by Node, including omitted/falsy host and custom lookup, with a regression that observes zero unowned accepts. No implementation changes were made in this review.

## Signatures, option combinations and ownership

Node normalizes positional calls using isPipeName/toNumber ([runtime](node22-net.js), lines 205–206, 282–314 and 1828). The guard uses a digits-only regex for direct Socket.connect (raw guard line 58). Direct numeric strings with a leading plus or whitespace are valid native TCP inputs but receive UNOWNED_IPC under the guard. Node selects IPC using !!path (runtime lines 1265–1286); the guard selects any string path (raw guard lines 64–67), so an empty path wrongly blocks an otherwise owned TCP connection. [Guarded raw outcomes](probes.stdout.log), lines 4–5 and 11, and [native controls](runtime-controls.stdout.log), lines 1–3, reproduce all three differences. F02 requires native-compatible normalization and truthy-path selection for supported forms.

The final probe records 22 connection attempts: 18 expectations met and 4 failed, plus a separate passing HTTP authority check. It confirms ordinary owned IPv4/IPv6, callback/positional calls, scalar and all:true pinned lookups, no-DNS localhost, owned IPC, owned IPC plus unrelated TCP options, closed-listener denial and asynchronous distinct errors for ordinary unregistered TCP/IPC. Nonempty unowned IPC plus an owned TCP port is correctly denied before any IPC accept. See [raw probes](probes.stdout.log), lines 1–27, [blocked rows](run-blocked.jsonl) and [probe results](probe-results.json). No external-address attempt was made independently.

The ownership check replays listen/close rows, filters by process liveness, and compares loopback address/port (with wildcard allowances) or IPC path/prefix (raw guard lines 18–45, 65–67). This is cooperative registry evidence, not proof of OS endpoint identity. PID/thread lifecycle, path aliases/replacement and registry tampering were not exhaustively qualified.
