## F1 — P2 — the wire-transcript oracle contradicts the specified encoder

- **Criterion:** PY02 (SPEC line 200), also the UTF-8/Unicode proof in PY04 (line 202).
- **Exact location:** `docs/02_spec/0218_pare100_python_sdk_stdio.md:185`, the clause “transcripts wire distintos apenas pelos IDs explicitamente diferentes”. Conflicting requirement: line **131**, mandatory `ensure_ascii=True`.
- **Actual source:** `packages/sdk/src/stdio.ts:115–119` uses `JSON.stringify(value)` and UTF-8 encoding. `packages/sdk/src/client.ts:82–86` supplies the turn params to that writer. There is no requirement in the actual v1 transport to use ASCII escape spelling.
- **Minimal counterexample (static, not executed):** the mandatory journey's `userMessage` value `Olá 🌿`. The Python encoder in line 131 emits the JSON string token `"Ol\u00e1 \ud83c\udf3f"`; the TS writer emits `"Olá 🌿"` in UTF-8. Even after accounting for explicitly different request IDs, these raw request frames differ. Both decode to the same valid string, and the proposal explicitly accepts astral Unicode. This failure occurs on the required happy path, without an adversarial peer or boundary-sized input.
- **Why material:** the first half of line 185 asks for semantic equality, but the wire clause then permits only ID differences. A literal byte comparison cannot pass the specified implementation; silently discarding all byte differences leaves the acceptance rule undefined. This is an oracle contradiction, not a request to change valid v1 Unicode or remove the Python encoder.
- **Requirement needed to resolve:** define two distinct checks in line 185: retain the original raw transcripts and verify each one's framing/encoding independently; compare decoded request/result/event values exactly, using an explicit typed ID correspondence. Permit JSON escape spelling, object-member ordering, and other semantically equivalent JSON serialization differences. Do not drop, rewrite, reorder arrays/events, replace identities, or normalize payload values to force equality. Alternatively specify a genuinely identical serialization design, but no such change is necessary for v1 interoperability. State which comparison determines PY02 so both a valid Unicode pair and a changed payload have determinate outcomes.

## F2 — P2 — client frame/error mapping conflicts with the actual TS transport

- **Criterion:** PY03 (SPEC line 201), PY04 (line 202), and per-state failure settlement in PY06 (line 204).
- **Exact location:** `docs/02_spec/0218_pare100_python_sdk_stdio.md:121`, “JSON/batch/notification inválidos fecham por frame”. This also conflicts with line **166**, which assigns invalid response format to `invalid_response`. The negative-case plan at line **187** requires closure but does not settle the kind/code disagreement.
- **Actual source:** `packages/sdk/src/stdio.ts:156–163` maps UTF-8/JSON parsing failure to `frame`. After successful parsing, the **client** branch at lines **324–345** maps missing/unknown/non-WRITTEN ID or invalid response envelope to `invalid_response`. The **server** branch at lines **529–535** instead maps invalid request envelopes/params to `frame`. Transport constants at lines **12–18** distinguish `frame=-32080` from `invalid_response=-32085`.
- **Minimal counterexample (static, not executed):** one fully written pending `sdk.hello` request, then inbound bytes `[]` followed by LF. This is valid JSON, so TS reaches its response callback, finds no correlatable ID, and closes with `SdkWireError(kind='invalid_response', code=-32085, outcome='unknown', retrySafe=false)`. Reading SPEC line 121 as the client framing algorithm instead yields `frame/-32080`; reading line 166 yields the other answer. An ID-less JSON-RPC notification object followed by LF has the same disagreement. Neither example relies on the additional duplicate-key, depth, or surrogate restrictions.
- **Why material:** fail-closed behavior alone does not satisfy a proposed public error contract. The text currently permits a Python implementation to use a different observable kind/code from the source it claims to project, while still passing a negative oracle that checks only closure. This is concrete contract drift, not an invented remote error or a need to accept notifications.
- **Requirement needed to resolve:** distinguish parsing/framing failures from parsed-invalid **responses**, and distinguish client ingress from the Node server's request ingress. On the client, valid JSON batch/notification/invalid response envelopes must terminate through `invalid_response/-32085`; invalid UTF-8/JSON, missing LF/partial EOF, and frame-size violations remain `frame/-32080`, subject to the explicitly documented extra Python JSON restrictions. Preserve the pre-settlement terminal cleanup and individual QUEUED versus WRITTEN outcomes. Amend the existing negative-case oracle to name the expected kind/code and both waiters' outcomes. No new wire code or method is needed.

## Other bounded design checks

These are design observations, not runtime PASS results:

- **Wire vocabulary and scope:** protocol version 1, the four methods, SDK error constants, seven local error kinds, numeric/string ID identity, and the null-ID non-correlation rule match the sealed protocol/client/validators/stdio sources. No resume/cancel/approval RPC is invented. The original P100-025 card at `scope/0378_backlog_paridade_integral.md:131–137` requires notifications, turn controls, transports, execute/resume/cancel, and depends on AUD0611-G01/P100-020. SPEC lines 9 and 218–229 preserve those remaining obligations rather than declaring the card complete.
- **Composition and authority:** `server.ts:107–140, 202–205, 274–295, 367–371` binds tenant, budget, policy, approvals, tools, and session store at the trusted host. Full/minimal capability behavior and session requirements match the proposal. The separate real-kernel tool-governance adapter is identified as synthetic, consistent with `stdio.test.ts:1133–1262`; it is not misrepresented as a v1 tool-selection parameter. The library has no spawn/discovery authority. Runner escalation is restricted to its own child and distinguishes adapter closure from process exit.
- **Events/catalog:** the physical supplied catalog is `packages/contracts/src/session-event-schemas.v1.json`, exported as `SESSION_EVENT_CATALOG_V1` by `session-events.ts:1–11`. Nine event schemas, required/extra-field behavior, UTF-16 lengths/trim, byte limits, exact envelope, tenant/session identity, sequence/cursor/page identity, correlation checks, year-zero-compatible timestamp validation, and compaction ordering correspond to `session/events.ts` and `sdk/validators.ts`. The fingerprint is the schema/definitions projection at `session/events.ts:186–197`, not an event-payload digest. The spec keeps that distinction and requires all nine projected values to be compared with the public TS implementation later. No nine-hash runtime computation was performed here.
- **Cross-language restrictions:** the spec deliberately declares whole-frame depth/node limits, duplicate-key rejection, isolated-surrogate rejection, completed-write response guard, and conservative event byte estimation. These can reject otherwise TS-accepted inputs, but the exceptions are named instead of silently weakening tenant/schema/fingerprint checks. Safe integer versus bool, binary64 handling, UTF-16 astral lengths, JS trim, finite costs, and the conservative numeric size allowance do not establish another material design defect in this bounded review.
- **Bounds/reservation/backpressure:** counts include queued plus written pending; accepted request bytes stay charged through settlement; IDs remain lifetime-bounded; admission refuses only new work. The specified premeasurement avoids allocating an unbounded escaped string before its cap check. One writer, an offset over a memoryview, partial-positive writes, EAGAIN readiness, bounded EINTR retries, and no frame interleaving are feasible using nonblocking POSIX pipes and SelectorEventLoop callbacks. Node's callback-plus-drain barrier is correctly left in the actual server rather than copied into Python's syscall semantics. The quantum/remainder/continuation rules provide a concrete bounded reader design; none implies a generic blocking BinaryIO adapter.
- **Critical terminal state:** monotonic admission deadlines include queue/write time; failure closes collectively and classifies each request by its own attempted-write state. Local Task.cancel translation is unusual but expressly proposed for T3 review, with shield/terminal cleanup and no remote-cancel claim. EOF with and without a tail, late/duplicate/type-swapped IDs, invalid results, fixed local error messages, no retry/reopen, callback/timer cleanup, and borrowed FD ownership are specified. Attach rollback and host exclusivity/lifetime assumptions make the proposed selector approach implementable on its declared target. Runtime proof of these mechanisms, exact memory high-water behavior, and child cleanup remains future work; no platform or timing certification is conferred by this review.
