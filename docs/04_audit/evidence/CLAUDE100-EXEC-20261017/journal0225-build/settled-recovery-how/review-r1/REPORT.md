## Mandatory grouped correction

### HOW-R1-01 — close reconstructed identity and timestamp

**Gap:** proposal:50–60 leaves the timestamp's real field to implementation and does not finish the step-attempt/pending/ref acceptance predicate. [S09 contracts](sources/before/09-execution-v2.ts.source.txt):85–101 provides `completedAt?:string`, `startedAt`, numeric step `attempt` and observationRefs; it provides no updatedAt or journal attempt UUID. [S04 runtime](sources/before/04-iterative-runtime.ts.source.txt):2055–2081 writes native completedAt for terminal steps and step attempt1. [S03 journal](sources/before/03-effect-journal.ts.source.txt):16–25,274–301,338–345 uses a different, string effect attemptId and exact proposal hash. Nonempty UUID must not be presented as equality with the numeric step attempt.

**Smallest concrete completion:** choose `settledStep.completedAt` as reconstructed Observation.timestamp, require a valid durable timestamp and stop if missing/invalid; do not fall back to now, infer updatedAt, or claim the lost observation's original time. Fix the whole predicate: a unique matching TOOL/SUCCEEDED row with the deterministic expected stepId, tenant/execution/pending step, supported native decision type and numeric attempt1 for this current writer; pending step is the next uncompleted checkpoint step; tool/version/fingerprint/input and any acceptedDecision are consistent. Require one nonempty valid observationRef not colliding with another observation or step; reconstruct only an **absent** TOOL_RESULT, never replace a saved UNAVAILABLE/invalid result. Preserve step row/ref/attempt byte-for-byte. Require an own journal result property (null allowed), CONFIRMED, exact tenant/operationKey and the existing proposalHash computed from the captured original tool/input/composition. State that journal attempt identity is the existing immutable confirmed operation/proposal binding established by native reservation/confirmation, not a comparison to step.attempt; empty/invalid attempt or unproved native binding stops. No new cross-record UUID field is proposed. Add negatives for wrong step attempt, duplicate matching rows, ref collision, missing completedAt and inconsistent pending/accepted decision, in addition to proposal:78–81.

This freezes supported native provenance; it does not authorize deriving identity from output or writing/reopening a settled step. The lead reports mapStep preserves completedAt; that mapper was not independently opened outside these16 sources.

### HOW-R1-02 — specify the one-step accounting delta and staged CAS failure behavior

**Gap:** proposal:64–70 says preserve accounting/complete pending state but does not resolve the witnessed steps0→1 gap. Blindly reusing the full-saved-result branch would add countedSteps without incrementing usage.steps (S04:959–980); blindly incrementing that generic branch would overcharge checkpoints already containing the saved result. A read callback is not settlement and must not touch receipts or toolCalls.

**Smallest concrete completion:** define a separate missing-observation recovery transition. Starting from the trusted pending checkpoint and the uniquely proven uncheckpointed succeeded step, stage the reconstructed observation plus the completed cognitive state: advance run/state.stepNumber to that pending step, clear the consumed pendingDecision/pendingStepNumber/pendingApprovalId and acceptedDecision, set native selectedCapability/lastToolObservation, add its signature once and mark it counted/inFlightCounted=false. Restore **exactly one** usage.steps for this new recovery branch only; keep the checkpoint's existing toolCalls, modelCalls, tokens, cost and SETTLED admission receipts unchanged. Leave the existing full-saved-result resume accounting unchanged. Do not fabricate the writer's lost activeDurationMs; retain durable duration and ordinary current-reader elapsed accounting.

Use the existing pre-runLoop `await persistCheckpoint(run)` at S04:1059 (CAS implementation2142–2164), with the loaded checkpointId+digest, before any new decision/model/dispatch. No public hook is needed. The HOW must explicitly keep the staged state intact through applyResume, bound/catch the read and validation, honor existing cancel/pause/deadline controls and require APPLIED with the expected returned token. On get error, timeout, CAS rejection/throw or stale lease/fence, return the redacted conservative stop with the original durable checkpoint preserved; do not fall through to runLoop or issue a generic-finalize second save that could commit the staged state after the failed recovery attempt. S04's current insertion point is before the outer try (919–992), and generic catch/finalize can write unless preserveCheckpoint is selected (1066–1083,2332–2351); therefore the failure path needs to be named, not assumed. Bound guards remain the existing native store guards; a successful read/stamp grants no lease. J13 remains required and NOT_RUN for this proposed path.

Add a focused oracle for recovery-only steps+1, unchanged prior receipt/usage fields, unchanged generic full-saved-result count, failed recovery CAS with zero subsequent writes/model/body, and a later retry loading the then-current native token. No settled step mutation, reserve/execute/confirm/fail/markUncertain call or receipt resettlement is permitted.

### HOW-R1-03 — pin the callback transport and distinguish the two symbol descriptors

**Gap:** proposal:22–25,38–44,97–100 defines the record stamp flags but leaves the private callback's copy behavior and stamp value unspecified while listing survival as a risk. The **record** stamp must be nonenumerable; making the **tool callback** nonenumerable would drop it in a tool object spread. This is a concrete transport issue, not a reason for a public callback option.

**Smallest concrete completion:** fix the exact record stamp value (for example immutable own data value `true` at the specified versioned Symbol.for key), require the matching value plus enumerable=false/configurable=false/writable=false and reject accessors without invoking them. Attach the module-private recovery callback as an **enumerable own symbol data property** on the native wrapped tool, following the existing NATIVE_EFFECT_JOURNAL transport pattern at S03:251–271,331–334; read it by own data descriptor and require a function. Do not impose the record stamp's nonenumerable flag on the tool callback. [S07 factory](sources/before/07-createOperationalHarness.ts.source.txt):238–258 prepares the tool registry before native journal wrapping; S04:892–897,938 and S07:119 use that registry directly. [S08 preparation](sources/before/08-complete-tool-results.ts.source.txt):54–68 copies enumerable tool properties by spread. Thus this specified private callback can survive the shown path/copies, while closing over original tool/journal/fingerprint and using only get. A clone/adapter that strips the record stamp must stop, never regain it from a textual field, class label or result shape.

Explicitly retain the declared trust boundary: Symbol.for is discoverable/forgeable by arbitrary installed programmatic code and nonenumerability is not authentication. Trusted composition/adapter performs actual readiness+decode; the callback checks native ownership plus exact bindings, and model/tool JSON cannot convey the symbol. Unmarked custom, legacy0 and InMemory returns stop; malicious installed code that fabricates the exact symbol/descriptor is outside S01:96–102's stated hostile-code boundary, not newly secured by this protocol. If rejection of such installed-code forgery were required, this HOW would be insufficient and a new attestation/security design would be material scope. That stronger requirement is not established here. Pin the callback round-trip and descriptor negatives in the focused plan; no runtime proof is claimed now.

## Remaining judgments and authority

The payload helper path is appropriate: S08:75–102 produces SUCCEEDED/UNAVAILABLE for context-size/depth/node overflow; S04:1453–1464 blocks model entry on it. Reconstructed unavailable output must still be checkpointed through the guarded CAS and stop before the next model; no summary or stamp promotes it to COMPLETE. Existing complete saved results and their binding validation remain intact. Invalid/untrusted/legacy/custom returns never bypass the old stop. Logical output still has no symbols and is TOOL/UNTRUSTED.

Current conservative handoff is the safe baseline but leaves the demonstrated recovery gap; a plain generic get/re-execute path would violate the frozen regression or lose native qualification. The proposed internal path, completed as above, is the minimum viable direction: no inverse harness→persistence import, new dependency/export/option/schema or rewrite of settlement authority is needed. Tradeoff: an internal symbol protocol and stricter recovery eligibility, with handoff if metadata is lost. Existing parent/fence/outer safety remains at native CAS; this review has not inspected an additional store/guard source or certified those guards by label.
