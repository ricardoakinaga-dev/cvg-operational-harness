## Bounded implementation proposal

The first change should be a **value/effect split**, not an expanded allowlist. Keep an effect/capability result for the operation, and a separate abstract result shape: primitive, closed own data record, optional descriptor, finite descriptor table, opaque prototype token, known module namespace with export summaries, capability set, or Unknown. A descriptor has guaranteed boolean metadata under native semantics, while its value/get/set fields retain receiver-field capabilities. An opaque prototype can be compared by identity; dereferencing or exporting it returns Unknown unless separately proven.

Extend the existing stable own-scalar proof narrowly: fresh local object allocation, only explicit own scalar data fields, finite literal key union, lexical binding identity, all references audited for writes/aliases/callback escapes, no computed definitions/spreads/**proto**/accessors/methods in the initial rule. Const is a binding constraint, not object immutability. Prove every receiver/key alternative; property absence must not silently fall through to prototypes. A known loader/evaluator field stays tainted even in a perfectly closed object. Alias/assignment transfer must preserve shadowing and assignment-pattern writes.

For native descriptor/prototype summaries, require **trusted intrinsic identity and semantics**, not global spelling or type declarations. With that authority, descriptor booleans and presence tests can be modeled accurately even when an unknown receiver leaves an origin effect. Closed receivers permit full inertness for descriptor lookup or own-data Reflect.get. Unknown receivers, Proxy potential, getter dispatch, arbitrary construction, exported reflection functions, runtime code generation, and unknown module targets remain refused.

Use bounded monotone transfer and fail closed on exhaustion. Proposed implementation limits are 16 keys/union alternatives, depth 64 and 4096 local proof nodes, subject to builder review. A budget limit produces Unknown, never a truncated proof. First integrate in boundary-code-execution.mjs and preserve residual effect refusal through check-product-boundary.mjs. Do not broaden literal module resolution or infer safety from declaration closures.

For the 114 helper sites, metadata can be summarized from exact helper bodies, but clearing the helper as a whole needs exact runtime namespace/export/getter summaries and non-Proxy/mutation provenance for its receivers. Match the supported structure and prove each argument; do not skip a helper name, path, package or fingerprint. The helper name can also be shadowed or rebound, and a module export can be a getter returning a loader.

**Why the current seven core identities cannot all be eliminated from this packet alone:** stableSerialize accepts unknown values; the plain-record check is structural and cannot distinguish a Proxy. The packet contains no enforced pristine-realm policy or trusted recursive JSON-only allocation contract for all callers. Dependencies and callback consumers may mutate globals or carry capabilities. A contract/runtime policy must establish these properties, or a much larger relevant closure must be proven. JSON types, tests/dev labels, Object.freeze and a locally stable alias do not supply that proof. A future contract is a separate reviewed change, not authority granted by this sidecar.
