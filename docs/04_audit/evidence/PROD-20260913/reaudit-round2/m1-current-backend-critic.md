3. **P1 / FAIL — wrapping task creation in transaction breaks concurrent replay recovery.** `packages/persistence/src/journeys-postgres.ts:381` and `packages/persistence/src/postgres.ts:2947`: createTask catches unique violation then SELECTs winner inside the now-aborted transaction. Two real pool clients, same session/source/idempotency key, barrier immediately before tasks INSERT: one succeeds, other throws **25P02 current transaction is aborted**; one persisted task, zero audit events. Exact probe `/tmp/m1-pg-probe.ts`, log `/tmp/m1-pg-probe.log`. Criterion same-key concurrent calls retain replay behavior and audit uniqueness: FAIL. Use conflict-safe insert or a savepoint; do not SELECT after an unhandled transaction-aborting statement.

4. **P1 / FAIL — preflight accepts a role with tenant isolation defeated by policy.** `apps/worker/src/postgres-role-preflight.ts:119` checks RLS/FORCE flags, not effective policies. Real SQL on that role, `cvg.tenant_id` set to tenant A, read an outbox row for tenant B. Logs above. Literal flags check works, but worker tenant-isolation assurance fails under a permissive policy. Criterion SQL policy isolation before first claim: FAIL. Need bounded validation of expected policies/effective isolation; boolean RLS flags alone cannot establish it.
