# Configuração admitida preservada durante a chamada

O commit privado `5be0ca7078ceda425a7335eca3c36243dd146ee1`, sobre `4f86d71a4b5184e3d54a2a17e5cf5c51bd23d993`, corrige a releitura de perfis mutáveis durante uma chamada ao gateway. `generate` passa a capturar os perfis primário e de fallback, incluindo preços, antes do primeiro await. As cópias pertencem à chamada; os objetos do host continuam mutáveis e uma chamada futura observa sua configuração atual.

O problema foi reproduzido pelo [consumidor público anterior](../public-authority-probe/REPORT.md): o pedido entregue ao provider ficava congelado, mas o evento de retry e o resultado anunciavam outro modelo. As regressões também demonstraram que uma alteração no perfil de fallback podia alcançar o corpo antes de ele ser admitido com a configuração original. Alterar só o campo do evento deixaria preço, flags de despacho e resultado expostos à mesma releitura.

Três testes foram acrescentados ao arquivo existente; os 16 anteriores conservam seu prefixo byte a byte. Na fonte anterior, dois testes novos falharam e o caso de configuração futura passou. Na correção, os 329 testes do gateway passaram, e os 19 focais foram conferidos novamente após a formatação do arquivo. Typecheck, lint, formato e build dos vinte workspaces passaram.

O mesmo oráculo público, sem alteração de bytes ou expectativas, passou de8/9 para9/9 com o novo tarball. A comparação de 883 arquivos encontrou apenas `gateway.js`, seu source map e o buildinfo alterados; `gateway.js` é o único JavaScript de runtime diferente. As 19 declarações e os 38 exports públicos do gateway permanecem iguais. Os 59 arquivos do tarball novo foram conferidos contra o contexto compilado e a instalação física. Os processos terminaram sem recursos Node ou grupo residual.
